# Complete-history trigger control and independent confirmation

This opt-in procedure was frozen before opening the independent confirmation event payload. The unchanged
procedure subsequently passed all 52 paths over 28,148 independent CE events; that result confirms stock replay,
not the fast arm. R7 is now paused by user as of 2026-11-05 06:10 EST, with no R7 jobs running;
see [pause/resume assignments and gates](PAUSE_RESUME.md). The procedure does not promote
trigger defaults or certify a fast-digi arm. Keep the exact code snapshot, configuration and evidence hashes in
private receipts; do not commit production payloads or site paths.

## Development result

The CE development control contains 28,044 stored preselection-parent events from ten original input files.
All 52 scheduled physics paths agree in accepted bits, retained state, `wasrun` and mapped endpoints across
1,458,288 event-path comparisons. The original first-pass 56-path status matrices are preserved. On every one
of the 21,078 original selected events, all six serialized digi/waveform/timing products and all 56 original
packed words are exact. Original and replay schedule IDs resolve to their ordered bit:path lists in the
embedded registry. This is one development production job, not independent confirmation or generated efficiency.
All replay raw indices/packed words differ after deliberate digitizer/decorator removal; never call that full-art
serialization identity. The earlier selected-stream control remains a counterexample to dropping source history.

## Frozen procedure

1. Use the candidate file's embedded Digitize configuration and actual successful production log. Check exact
   parent opened order, seed, released runtime, geometry, conditions and complete processed-event count. Do not
   infer these from development menu names. Record the independent source's disjointness before payload use.
2. Catalogue exact parents read-only, stream them only to private unsynced scratch, and verify catalogue size,
   Adler-32 and source/destination SHA256 receipts. No new Geant4, modified seeds or substituted parent shards.
3. Prepare full original Digitize physics/services/module set from process start. Retain CRV and other stochastic
   modules even if trigger paths do not consume their products. Only output selection/filename and staged source
   locations change. Switch the existing output at each original input-file boundary; do not use a combined
   subrun-sorted output or restart the process per parent.
4. Require successful art, finished highest-cycle entries equal to the original processed count, ten-parent-style
   complete identity coverage for the actual parent count, and original file order. Within each file, use the
   default RootInput numeric event traversal, not physical basket-entry order. `noEventSort` does not preserve
   arbitrary cross-subrun history. Fail on duplicate/missing identities or count/order disagreement.
5. Require all original selected events present in the complete regeneration, with zero mismatches in all six
   serialized products and every original packed path word. Verify configuration/reference/candidate byte
   receipts. The full-regeneration original output selector must reproduce the original selected event set;
   selected overlap alone cannot establish that independent check.
6. Prepare one second pass over the numbered original-parent files in original order. Retain original timing,
   conditions and physics cuts; remove digitization/truth decorators and truth-only paths using the recorded
   transformation. Do not truth-gate source events. Both stock and any later fast arm must evolve their own
   filter-invocation history; a stock ordinal sidecar is not valid after upstream fast-arm reach changes.
7. Bind exact prepared FCL, configuration, ordered input bytes and count before runtime and again at postflight.
   Preserve original TriggerResults. Require exactly one successful art completion, expected finished entries,
   independently decoded ROOT/log/source IDs/order, unchanged first-pass words and valid schedule registry
   bindings for original and replay.
8. Report every scheduled physics path separately. All accepted/state/`wasrun`/mapped-endpoint differences must
   be zero for a stock control. Report raw index/packed differences independently, without excusing or relabeling
   them equal. Ready is accepted but not Pass; exceptions are never a normal matching endpoint certificate.
9. If only postprocessing fails, retain completed art and fix/re-run metadata analysis only. Never fit counter
   offsets, copy stock decisions, drop difficult paths, substitute output-OR agreement or use a short pilot as
   the complete result. Any candidate physics/selection change after confirmation opens requires a new declared
   development/confirmation split; do not tune on held-out per-event outcomes.

## Claim boundaries

A passing independent CE control establishes this procedure for that additional CE production job. It does not
validate the different cosmic-era module settings or R2/R6 fast products. Run a cosmic control using its own
provenance, then tracker-only, calo-only and combined fast arms on matched complete-event inputs. Separate art
files sharing event IDs are not an event join. Keep paired independent-shard statistics distinct from deterministic
control equality. No binomial uncertainty or throughput multiplier follows from a single development job.

Quiet like-for-like trigger timing excludes printing and production digitization/truth/source/output work;
shared reconstruction attribution is weighted by invocations over all input events. The verbose full control
is not a latency benchmark. The development two-final-selection JAX component now agrees on measured
hybrid arrays with actual upstream reach retained; that does not establish upstream reconstruction emulation,
physics validity or independent-history confirmation. Any extension must retain the per-path gates in
[JAX_SELECTION.md](JAX_SELECTION.md).
